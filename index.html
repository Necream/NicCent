核心理念

NicCent 不是 Agent 框架，也不是传统的 MCP 请求-响应系统。它是一个以 共享状态（ColyVar） 为中心的扩展生态：状态变化触发扩展协作，AI 仅在需要时被唤醒以完成任务。

PAW — Powerful AI Widget

在NicCent发布后可用

PAW 是 AI 扩展运行时，模型由扩展提供而非内置。支持 OpenAI、DeepSeek、Claude、Qwen、Gemini、以及本地模型适配器。

Model Agnostic
扩展提供模型，运行时保持中立。
Sandboxed
隔离执行，受控资源使用。
Event-driven
由 ColyVar 变化与 Scheduler 事件触发。

架构对比

下面对比三种常见模式的关键维度，帮助理解您 NicCent 的定位。

Pattern 触发方式 运行模型 资源消耗 协作模式 最佳场景
MCP 单次外部请求触发 按请求短时调用 低到中（按需） 单次工具链调用 即时问答、工具链式任务
Agent 常驻进程或长期任务触发 常驻智能（持续运行） 高（长期占用） 单体或内部多模块协作 长期代理、持续监控与决策
NicCent ColyVar 状态变化 / 调度器事件 按事件唤醒（AI 睡眠） 低（事件驱动） 多扩展基于共享状态协作 低成本可组合扩展生态、按需 AI 调用

短句：MCP — 按请求调用工具；Agent — 常驻代理；NicCent — 状态驱动、按需唤醒、模块化协作。
